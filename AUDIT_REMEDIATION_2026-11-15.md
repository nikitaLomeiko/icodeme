# Журнал исправлений по `CODE_AUDIT_2026-11-15.md`

Дата: 15 ноября 2026 года. Исходное состояние рабочего дерева перед работой было чистым, HEAD `43053c2 fix`. Изменения ниже выполнены по запросу пользователя. Старый аудит `AUDIT_REPORT.md` и новый `CODE_AUDIT_2026-11-15.md` не изменялись.

## Что сделано

1. Прослежены цепочки учебного плана, запуска Docker, OAuth, профиля, избранного и клиентского состояния. Проверены контракты запросов и ответы обеих сторон.
2. К существующему RTK Query API добавлены вызовы генерации модулей, уровней, шагов и содержимого; в интерфейсе добавлены кнопки с состояниями загрузки и ошибки. Кнопка «Продолжить» в списке планов открывает выбранный план.
3. Шаги Python и JavaScript получают доверенную конфигурацию запуска на сервере. Если для языка отсутствует среда выполнения, генерация практических шагов возвращает явную ошибку. Тестовые Dockerfile больше не устанавливают зависимости из пользовательского `requirements.txt`; в образах и при запуске задан UID 10001.
4. Добавлен серверный маршрут сдачи теста. Ответы оцениваются по сохранённому тесту, завершение шага фиксируется атомарно и повторно не записывается. Вопросы без ключа проверки не входят в порог 70%. Клиент отправляет ответы после окончания теста и показывает статус сохранения.
5. Поиск шага теперь делает индексируемый запрос MongoDB по `userId` и `stepId`, вместо загрузки всех планов. Содержимое созданных шагов хранится в отдельной коллекции `studyStepContent`; при чтении отдельного плана оно присоединяется к метаданным. При удалении плана удаляется и его содержимое.
6. GitHub OAuth проверяет подтверждённый email через GitHub API. Синтетический адрес удалён; отсутствие подтверждённого адреса завершает вход явной ошибкой.
7. Добавлена атомарная пользовательская квота на AI-генерацию: 30 вызовов в сутки, с TTL для счётчиков. Повторный запрос уже сохранённого содержимого возвращает результат без обращения к модели.
8. Поля профиля обновляются адресно через `$set`; опыт и достижения обновляются с проверкой исходного значения и повтором при конкурентной записи. Это устраняет перезапись старым снимком и попытку `$set` неизменяемого `_id`.
9. Удаление избранного проверяет `modifiedCount`. Клиент обновляет локальное избранное после успешного ответа, использует актуальное состояние store и сбрасывает MobX stores при смене аккаунта.
10. Тип ответа остановки контейнера исправлен. Профиль показывает состояния загрузки и ошибки с повторной попыткой. Фиктивный рейтинг убран. Production frontend использует относительный `/api/` и серверный rewrite к backend в Docker Compose.
11. Публичный ответ отправки кода восстановления унифицирован для существующего и отсутствующего адреса. Для сохранения действующего frontend flow возвращается идентификатор того же формата; различия времени ответа требуют отдельного анализа.

## Диагностика

- `tsc --noEmit --incremental false` для backend и frontend: успешно.
- ESLint на изменённых модулях backend и frontend: успешно. Два ранее существовавших нарушения FSD-границы в `code-step-view.tsx` и `documentation-step-view.tsx` остались за пределами точечной проверки и требуют переноса компонентов между слоями.
- Jest без WebSocket gateway: 4 набора, 11 тестов прошли. Добавлены 3 теста оценки тестов, включая вопрос без ключа проверки.
- Полный Jest: 4 набора прошли, 1 WebSocket gateway тест не запустился из-за `listen EPERM` на `127.0.0.1` в текущем sandbox; это ограничение проверки, а не подтверждённая ошибка приложения.
- `git diff --check`: без ошибок пробелов.
- Реальные MongoDB, Docker runtime, GitHub OAuth и AI не запускались. Не было развёртывания и browser end-to-end проверки.
