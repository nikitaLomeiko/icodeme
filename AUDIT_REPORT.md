# Технический аудит текущего рабочего дерева

Проверены основные цепочки frontend → API → NestJS-сервисы → MongoDB, а также авторизация, запуск Docker, генерация учебного плана, профиль, документы и тесты. Всего в `apps/backend/src`, `apps/frontend/src` и `apps/frontend/app` обнаружено **646 файлов**. Их структура и связи просмотрены, но построчный анализ всех 646 файлов не завершён; непроверенные области перечислены в конце. Выводы относятся к **текущему рабочему дереву**, в котором до аудита уже были многочисленные пользовательские изменения.

Диагностика TypeScript выполнена для обоих приложений командой `tsc --noEmit --incremental false`: оба запуска завершились без ошибок. Тесты, сборка, Docker и обращения к базе не запускались, поскольку они могут менять состояние.

**Статусы:** «код» — подтверждено анализом исходников; «диагностика» — подтверждено безопасной диагностической командой; «проверка» — для оценки фактического проявления нужна среда выполнения. Рекомендации ниже приведены только в отчёте.

## CRITICAL

### C-01 — Общая история ИИ-запросов всех пользователей

- **Категория:** безопасность, изоляция данных. **Статус:** код.
- **Место:** `apps/backend/src/core/ai/openai/chat-session.ts:9`, `apps/backend/src/core/ai/ai.provider.ts:6`, `apps/backend/src/modules/study/services/study-generation.service.ts:138`.
- **Проблема:** `ChatSession` хранит изменяемый `history` в поле экземпляра. Провайдер NestJS создаёт общий экземпляр сервиса, а каждый `send()` добавляет туда пользовательский запрос и передаёт всю историю модели. Разделения по пользователю или запросу нет.
- **Почему неверно:** контекст одного пользователя попадает в последующие запросы других пользователей. Массив также не ограничен по размеру.
- **Последствия:** раскрытие содержания чужих учебных запросов через ответы модели, смешение результатов, рост затрат и памяти, ошибки при параллельных вызовах.
- **Рекомендация:** сделать запрос к модели независимым: передавать локальный массив сообщений для каждого вызова. Если история действительно нужна, хранить её отдельно по пользователю и с ограниченным сроком жизни.

### C-02 — Production-образ backend не содержит шаблонов генерации

- **Категория:** поставка, функциональность. **Статус:** код.
- **Место:** `apps/backend/Dockerfile:39`, `apps/backend/src/modules/study/services/study-generation.service.ts:15`, `docker-compose.yml:18`.
- **Проблема:** сервис синхронно читает `data/prompts/*.txt`. Финальный образ копирует `node_modules`, `dist` и `package.json`, но не `data/prompts`. Compose дополнительно монтирует том в `/app/data`.
- **Почему неверно:** в новом production-развёртывании нужных файлов в контейнере нет; монтирование пустого тома их не создаёт.
- **Последствия:** маршруты генерации модулей, уровней, шагов и контента падают при чтении шаблона.
- **Рекомендация:** включить шаблоны в неизменяемую часть образа вне перекрываемого тома и вычислять путь относительно приложения. Проверять наличие шаблонов при запуске.

### C-03 — Запуск пользовательского кода имеет слабую сетевую изоляцию

- **Категория:** безопасность Docker. **Статус:** код; степень воздействия на инфраструктуру требует проверки.
- **Место:** `apps/backend/src/modules/ide/services/docker.service.ts:327`, `apps/backend/src/modules/ide/utils/docker-runtime.utils.ts:130`, `apps/backend/src/modules/study/factories/test-study-module.factory.ts:168`.
- **Проблема:** контейнер получает обычную сеть Docker и публикует случайный порт хоста без ограничения адреса привязки. Пользовательский код и зависимости из `requirements.txt` запускаются в этой среде.
- **Почему неверно:** лимиты CPU, памяти и PID не ограничивают исходящие сетевые запросы и доступ к внутренним сервисам, видимым из контейнера. `PortBindings` без `HostIp` расширяет доступность запущенного сервиса.
- **Последствия:** возможны обращения к внутренним адресам и внешняя публикация кода пользователя через порт хоста. Конкретная достижимость зависит от сетевой конфигурации сервера.
- **Рекомендация:** задать явную сетевую политику для сборки и запуска, привязывать порт только к нужному интерфейсу либо не публиковать его, ограничить права процесса, файловую систему и доступ к метаданным инфраструктуры.

## HIGH

### H-01 — Учётные записи не защищены уникальными индексами

- **Категория:** аутентификация, MongoDB. **Статус:** код.
- **Место:** `apps/backend/src/modules/auth/services/auth.service.ts:101`, `apps/backend/src/modules/auth/services/oauth.service.ts:53`, `apps/backend/src/core/database/database.provider.ts:20`.
- **Проблема:** регистрация и OAuth сначала ищут пользователя, затем вставляют документ. Уникальные индексы для `email`, `googleId`, `githubId`, `telegramId` не создаются.
- **Почему неверно:** две параллельные операции могут обе пройти проверку отсутствия пользователя. Поиск по email после этого становится неоднозначным.
- **Последствия:** дубли аккаунтов, ошибки входа и привязки провайдера.
- **Рекомендация:** нормализовать идентификаторы, создать уникальные индексы с учётом существующих данных и обрабатывать конфликт вставки.

### H-02 — Идентификация Google допускает эвристическую замену проверенного ID

- **Категория:** аутентификация. **Статус:** код; эксплуатируемость конкретной коллизии требует проверки.
- **Место:** `apps/backend/src/modules/auth/services/oauth.service.ts:86`.
- **Проблема:** при несовпадении `googleId` код считает допустимым совпадение нового ID с email пользователя или фрагментом URL его фотографии, после чего перезаписывает `googleId`.
- **Почему неверно:** URL фотографии и email не являются удостоверением личности Google-аккаунта. Логика миграции не отделена от обычного входа.
- **Последствия:** ошибочная привязка аккаунта; при подходящем совпадении — вход в чужую учётную запись.
- **Рекомендация:** сопоставлять аккаунт только по проверенному ID провайдера. Миграцию старых записей проводить отдельной контролируемой процедурой.

### H-03 — Публичный маршрут добавляет тестовые модули без ограничения

- **Категория:** авторизация, ресурсы. **Статус:** код.
- **Место:** `apps/backend/src/modules/study/controllers/study.controller.ts:46`, `apps/backend/src/modules/study/services/study-plan.service.ts:43`.
- **Проблема:** любой вошедший пользователь может многократно вызвать `POST /study/test/modules`. Каждый вызов добавляет большой тестовый модуль в сохранённый план.
- **Почему неверно:** служебная функция доступна как обычная продуктовая операция; нет проверки, что модуль уже существует, и нет квоты.
- **Последствия:** быстрое увеличение документов MongoDB до предела размера, рост ответов API и затрат на чтение и запись.
- **Рекомендация:** убрать маршрут из production или сделать его административным и идемпотентным.

### H-04 — Обновление профиля с frontend не соответствует DTO backend

- **Категория:** API-контракт. **Статус:** код.
- **Место:** `apps/frontend/src/entities/profile/api/profile.api.ts:28`, `apps/backend/src/modules/profile/dto/profile-data.dto.ts:24`, `apps/frontend/src/features/profile/ui/profile-edit.form.tsx:54`.
- **Проблема:** `PUT /profiles/me` отправляет только `about`, `avatar`, `name`, тогда как backend требует ещё `chips` и `position`.
- **Почему неверно:** тип мутации скрывает различие между данными формы и полным DTO. Глобальный `ValidationPipe` отклоняет запрос.
- **Последствия:** редактирование имени, аватара и описания возвращает 400.
- **Рекомендация:** определить общий контракт обновления. Для частичного изменения использовать отдельный DTO и `PATCH`; для полного — отправлять все обязательные поля.

### H-05 — Форма добавления языка отправляет поле, которого нет в API

### H-06 — Сохранение плана может потерять конкурентные изменения

- **Категория:** MongoDB, согласованность данных. **Статус:** код.

### H-07 — Избранное документа также обновляется по схеме «прочитать–перезаписать»

- **Последствия:** исчезновение сохранённых закладок, повторяющиеся записи.
- **Рекомендация:** выполнять атомарные операции по `documentId` и `favorite.id`, задать правила уникальности и проверять результат записи.

### H-08 — Не хватает индексов для основных запросов

- **Категория:** производительность, MongoDB. **Статус:** код.
- **Место:** `apps/backend/src/core/database/database.provider.ts:20`, `apps/backend/src/modules/study/services/study.service.ts:49`, `apps/backend/src/modules/auth/strategies/jwt.strategy.ts:31`.

- **Почему неверно:** TTL-индекс по `expiresAt` не ускоряет эти фильтры. Проверка сессии выполняется на защищённых запросах.
- **Последствия:** сканирование коллекций и рост задержек вместе с числом пользователей.
- **Рекомендация:** добавить индексы под реальные фильтры; для идентификаторов аккаунта и однозначных профилей — уникальные. Перед созданием проверить и устранить дубликаты.

### H-09 — Экспорт Markdown в HTML допускает активный код и опасные ссылки

- **Категория:** безопасность экспорта. **Статус:** код.
- **Место:** `apps/frontend/src/entities/document/model/utils/markdown-to-html.ts:21`, `apps/frontend/src/entities/document/model/utils/markdown-to-html.ts:213`, `apps/frontend/src/entities/document/model/utils/markdown-to-html.ts:569`.
- **Проблема:** исходный Markdown помещается в HTML до общего экранирования; произвольные HTML-теги сохраняются. Адреса ссылок экранируются как атрибуты, но их схема не ограничивается, поэтому возможен `javascript:` URL.
- **Почему неверно:** локальный экспорт превращает недоверенный текст, в том числе полученный от ИИ, в исполняемый HTML-документ.
- **Последствия:** при открытии скачанного файла исполняется внедрённый скрипт или опасная ссылка.
- **Рекомендация:** использовать Markdown-парсер с отключённым сырым HTML, санитарную обработку готового HTML и разрешённый список схем ссылок (`http`, `https`, при необходимости `mailto`).

### H-10 — Повторный запуск IDE может остановить новый контейнер из старого запроса

- **Последствия:** подключение к устаревшему контейнеру, остановка актуального контейнера, утечки контейнеров до серверного TTL.
- **Рекомендация:** присваивать каждому запуску номер поколения, игнорировать устаревшие ответы и немедленно останавливать созданный ими контейнер.

### H-11 — Неуспешный запуск терминала нельзя повторить на том же шаге

- **Рекомендация:** хранить явные состояния `idle/starting/ready/error`, сбрасывать ключ при неудаче и предоставлять действие «Повторить».

- **Категория:** конфигурация. **Статус:** код; фактический дефект зависит от переменных окружения.

### M-02 — Backend не обеспечивает лимит времени запуска кода из настроек шага

- **Рекомендация:** сделать серверную операцию инициализации идемпотентной либо продолжать с последнего успешно выполненного шага.

### M-07 — Кэш учебного шага может бесконечно обходить сервер

- **Категория:** состояние frontend. **Статус:** код.
- **Место:** `apps/frontend/src/widgets/step-shell/lib/hooks/use.study-step.ts:22`.
- **Проблема:** если шаг найден в Redux, запрос `getMyStudyById` отключается независимо от давности данных.
- **Последствия:** после изменения или удаления плана в другой вкладке показывается устаревший шаг и его настройки запуска.
- **Рекомендация:** использовать RTK Query как источник данных с правилами повторной проверки, а Redux хранить только выбранные идентификаторы и UI-состояние.

### M-08 — Чтение избранного документа не защищено от устаревшего ответа

- **Категория:** React, состояние. **Статус:** код.
- **Место:** `apps/frontend/src/entities/document/ui/document.tsx:28`.
- **Проблема:** при смене `documentId` прежний асинхронный запрос может завершиться позже и записать ссылки старого документа в общий MobX store. Эффект установки `documentId` также не зависит от самого `documentId`.
- **Последствия:** пользователь видит и изменяет закладки другого документа.
- **Рекомендация:** отменять прежний запрос или сверять ID перед записью; включить `content` и `documentId` в зависимости эффекта.

### M-09 — Ответ `getDocumentFavorites` заявлен как обязательный, но может отсутствовать

- **Категория:** API-контракт. **Статус:** код.
- **Место:** `apps/backend/src/modules/profile/services/profile-storage.service.ts:35`, `apps/backend/src/modules/profile/controllers/profile-storage.controller.ts:26`.
- **Проблема:** при отсутствии закладок сервис возвращает `{ success: true, data: undefined }`, хотя контракт контроллера объявляет `IFavorite`.
- **Последствия:** клиенты вынуждены угадывать значение отсутствия; проверки типов создают ложное чувство безопасности.
- **Рекомендация:** возвращать `null` с явным типом либо 404, согласовать это с frontend.

### M-10 — Синхронное чтение шаблонов блокирует event loop

- **Категория:** производительность. **Статус:** код.
- **Место:** `apps/backend/src/core/storage/base/base-file-storage.ts:7`, `apps/backend/src/modules/study/services/study-generation.service.ts:138`.
- **Проблема:** каждый запрос генерации синхронно читает один и тот же файл.
- **Последствия:** задержка остальных запросов в процессе при медленном диске или высоком числе вызовов.
- **Рекомендация:** загружать и проверять неизменяемые шаблоны один раз при старте либо читать асинхронно.

### M-11 — История и форма результата ИИ недостаточно ограничены

- **Категория:** валидация, ресурсы. **Статус:** код.
- **Место:** `apps/backend/src/modules/study/guards/study-type.guards.ts:103`, `apps/backend/src/modules/study/services/study-plan.service.ts:100`.
- **Проблема:** guards проверяют базовые типы, но не ограничивают размер строк, число модулей, уровней и вопросов. Результаты добавляются в Mongo-документ целиком.
- **Последствия:** неожиданный ответ модели способен создать чрезмерный план, тяжёлые ответы API или документ больше лимита MongoDB.
- **Рекомендация:** ввести размерные ограничения и проверяемую схему для каждого ответа модели до сохранения.

### M-12 — Таймер теста сбрасывается при повторном входе на вопрос

- **Категория:** логика теста. **Статус:** код.
- **Место:** `apps/frontend/src/features/quiz/ui/components/timer.provider.tsx:14`, `apps/frontend/src/features/quiz/model/store/quiz.slice.ts:62`.
- **Проблема:** deadline вычисляется заново при каждом изменении `currentIndex`; переход назад и вперёд восстанавливает полный лимит времени вопроса.
- **Последствия:** пользователь может обойти ограничение времени, если навигация по вопросам разрешена.
- **Рекомендация:** хранить абсолютный deadline или оставшееся время отдельно для каждого ID вопроса.

### L-01 — Непоследовательная терминология и стиль затрудняют чтение

### L-02 — Служебный обработчик навигации выводит данные в консоль
