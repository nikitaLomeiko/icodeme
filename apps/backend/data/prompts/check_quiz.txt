Задача: Проверить решенный квиз, найти ошибки в ответах пользователя и дополнить структуру квиза информацией об ошибках.

Контекст:
- квиз: #quiz#.

**Входные данные (JSON-структура решенного квиза):**

{
"title": "Название теста",
"description": "Описание теста",
"questions": [
{
"title": "Вопрос 1",
"description": "Описание вопроса",
"type": "abcd" | "input" | "code" | "true/false",
"variants": [ ... ], // для type = "abcd"
"inputs": [ ... ], // для type = "input"
"code": { ... }, // для type = "code"
"truefolse": { ... }, // для type = "true/false"
"errors": [] // массив ошибок (пустой при отправке)
}
]
}


**Твоя задача:**
Проанализировать каждый вопрос и сравнить ответы пользователя с правильными ответами, которые указаны в свойствах `correct`, `correctCode`, `correctResult`, `correct` (в `truefolse`) и т.д.

**Логика проверки по типам вопросов:**

1.  **Тип `'abcd'`:**
    *   Сравни выбранный пользователем вариант (нужно определить, какой вариант был выбран - обычно это поле `isSelected` или `userChoice` - если такого нет, значит нужно смотреть на флаг `isTrue` у вариантов - если у варианта `isTrue: true`, значит пользователь его выбрал)
    *   **Ошибка:** Если выбранный вариант не совпадает с вариантом, у которого `isTrue: true`.
    *   **Сообщение об ошибке:** "Выбран неверный вариант ответа. Правильный ответ: [содержимое правильного варианта]"

2.  **Тип `'input'`:**
    *   Для каждого `IInput` в массиве `inputs` сравни значение из поля `input` (ответ пользователя) с массивом `correct`.
    *   Проверь вхождение без учета регистра (toLowerCase), но сохрани оригинальное сообщение об ошибке.
    *   Учти возможные варианты из массива `correct`.
    *   **Ошибка:** Если введенное значение не совпадает ни с одним из вариантов в `correct`.
    *   **Сообщение об ошибке:** "Неверный ответ. Ожидалось: [первый вариант из correct]"

3.  **Тип `'code'`:**
    *   У тебя есть объект `code` с полями:
        *   `code` - код, который написал пользователь
        *   `correctCode` - массив правильных вариантов кода
        *   `correctResult` - массив правильных результатов выполнения
    *   **Проверка кода:** Сравни `code` с каждым вариантом из `correctCode` (без учета пробелов и переносов строк)
    *   **Проверка результата:** Если есть `correctResult`, сравни результат выполнения с ожидаемым
    *   **Ошибка:** Если код не совпадает ни с одним правильным вариантом ИЛИ результат не совпадает с ожидаемым
    *   **Сообщение об ошибке:** "Код содержит ошибку. [конкретное замечание]" или "Ожидаемый результат: [правильный результат]"

4.  **Тип `'true/false'`:**
    *   В объекте `truefolse` есть поле `isTrue` (утверждение) и поле `correct` (правильный ответ).
    *   Нужно понять, что выбрал пользователь (обычно поле `userAnswer` или `selected`).
    *   **Ошибка:** Если выбор пользователя не совпадает с `correct`.
    *   **Сообщение об ошибке:** "Неверно. Правильный ответ: [true/false]"

**Правила заполнения `errors`:**

*   Если вопрос отвечен правильно - оставь массив `errors` пустым.
*   Если вопрос отвечен неправильно - добавь в массив `errors` один или несколько объектов с полем `message`, где опиши ошибку понятным языком.
*   Формат ошибки: `{ "message": "текст ошибки" }`

**Формат вывода:**

1.  **Если есть хотя бы одна ошибка:**
    Верни ПОЛНУЮ JSON-структуру квиза, но с заполненными массивами `errors` в тех вопросах, где допущены ошибки.

2.  **Если ошибок нет (все вопросы отвечены правильно):**
    Верни просто число `200` без каких-либо JSON-оберток, пояснений и лишнего текста.

**ВАЖНО:**
- Никаких пояснений, вступлений или заключений — только JSON с ошибками или просто число 200.
- Будь внимателен при сравнении строк - учитывай пробелы, регистр, но для `input` используй `toLowerCase().trim()`.
- Для кода - удаляй все пробелы и переносы строк перед сравнением.
