Задача: Сгенерировать тест (quiz) для проверки знаний по конкретному шагу учебного плана. Тест должен быть представлен в виде JSON-объекта, строго соответствующего предоставленным TypeScript-интерфейсам.

Контекст:
- Язык программирования: #language#.
- Модуль: "#module_title#" ("#module_description#").
- Уровень: "#level_title#" ("#level_description#").
- Тема текущего шага: "#step_title#".
- Детали шага: "#step_description#".

**ИНТЕРФЕЙСЫ ДЛЯ ГЕНЕРАЦИИ:**

export interface INotation {
title: string;
description: string;
}

export interface IQuiz extends INotation {
questions: IQuestion[];
}

export interface IQuestion extends INotation {
type: 'abcd' | 'input' | 'code' | 'true/false';
variants?: IVariant[];
inputs?: IInput[];
code?: ICode;
truefolse?: ITrueFolse;
errors: IQuestionError[];
}

export interface IVariant {
char: string;
content: string;
isTrue: boolean;
}

export interface IInput {
label: string;
input: string;
correct: string[];
}

export interface ICode {
code: string;
correctCode: string[];
correctResult: string[];
}

export interface ITrueFolse {
isTrue: boolean;
correct: boolean;
}

export interface IQuestionError {
message: string;
}



**КЛЮЧЕВЫЕ ТРЕБОВАНИЯ К ГЕНЕРАЦИИ ТЕСТА:**

1.  **Структура верхнего уровня (IQuiz):**
    *   `title`: Короткое и емкое название теста на русском языке (например, "Проверка знаний: #step_title#").
    *   `description`: Краткое описание, что проверяет этот тест (2-3 предложения).
    *   `questions`: Массив вопросов (см. п.2).

2.  **Количество и типы вопросов:**
    *   Создай **от 3 до 5 вопросов**, которые покрывают ключевые аспекты темы "#step_title#".
    *   **Обязательно используй минимум 3 разных типа** вопросов из доступных (`abcd`, `input`, `code`, `true/false`) в одном тесте.
    *   Подбирай тип вопроса, наиболее подходящий для проверки конкретного знания.

3.  **Детальная генерация по типам вопросов:**

    *   **Для типа `'abcd'`:**
        *   Заполни поле `variants` массивом из 4 объектов `IVariant`.
        *   `char`: Строго одна заглавная буква латинского алфавита (A, B, C, D).
        *   `content`: Текст варианта ответа на русском языке.
        *   `isTrue`: Только один вариант должен быть `true`, остальные `false`.

    *   **Для типа `'input'` (КРИТИЧЕСКИ ВАЖНО):**
        *   Заполни поле `inputs` массивом объектов `IInput` (обычно 1-2 поля).
        *   `label`: Подсказка, что нужно ввести (например, "Введите название метода").
        *   `input`: Можно оставить пустой строкой (заполняется пользователем).
        *   `correct`: **Массив ВСЕХ ВОЗМОЖНЫХ ПРАВИЛЬНЫХ ВАРИАНТОВ**. Обязательно учти:
            *   Разный регистр: `["переменная", "Переменная", "ПЕРЕМЕННАЯ"]`
            *   Синонимы: `["функция", "метод", "процедура"]` (если контекст позволяет)
            *   Варианты написания: `["веб-сервер", "веб сервер", "вебсервер"]`
            *   Опечатки: если слово сложное, добавь 1-2 варианта с частыми опечатками
            *   Английские термины: если ожидается ввод английского слова, добавь варианты с русской раскладкой: `["function", "функтион"]`

    *   **Для типа `'code'`:**
        *   Заполни поле `code` объектом `ICode`.
        *   `code`: Исходный код на языке #language# для анализа (может содержать ошибку или быть неполным).
        *   `correctCode`: Массив строк с правильным вариантом(и) кода (если задание на написание/исправление). Если нет — пустой массив.
        *   `correctResult`: Массив строк с ожидаемым результатом выполнения кода (если задание на предсказание вывода). Если нет — пустой массив.

    *   **Для типа `'true/false'`:**
        *   Заполни поле `truefolse` объектом `ITrueFolse`.
        *   `isTrue`: Формулировка утверждения (сам вопрос).
        *   `correct`: Правильный ответ (`true` или `false`).

4.  **Обработка ошибок (поле `errors`):**
    *   Для КАЖДОГО вопроса заполни массив `errors`.
    *   Добавь 2-3 типичные ошибки, которые может совершить пользователь, с понятными пояснениями.
    *   `message`: Текст пояснения на русском языке (например, "Не учтен крайний случай при передаче null", "Забыли про мутабельность массивов", "Неправильный приоритет операторов").

5.  **Поля `title` и `description` для вопросов:**
    *   `title`: Краткая формулировка вопроса (например, "Что такое замыкание?").
    *   `description`: Более развернутое описание или дополнительный контекст к вопросу (может содержать пример кода).

**ПРИМЕР-ПОДСКАЗКА ДЛЯ ЗАПОЛНЕНИЯ `correct` В `input`:**
Если вопрос: "Как называется функция, которая вызывает саму себя?"
- `correct` должен быть: `["рекурсия", "Рекурсия", "рекурсивная функция", "recursion", "Recursion"]`

**ФОРМАТ ВЫВОДА:**
Выведи ТОЛЬКО валидный JSON-объект, соответствующий интерфейсу `IQuiz`. Никаких пояснений, вступлений или заключений — только JSON. Убедись, что JSON корректен и может быть распарсен.
